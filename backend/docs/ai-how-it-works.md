# Как работает AI-часть

Документ описывает путь от ответов анкеты до готовых гипотез: что делает поиск, что делает модель, что происходит, когда модель недоступна. Все имена файлов — относительно `backend/`.

## 0. Общая схема

```
анкета
  → досье                     lib/ai/dossier.ts
  → поиск по каталогу          lib/ai/retrieval.ts
  → модель (5–8, 9–11)         lib/ai/generate.ts + lib/ai/llm/
    или резервный путь         lib/ai/fallback.ts
  → постобработка              lib/ai/postprocess.ts
  → ответ клиенту              lib/sofi-pipeline.ts
```

Пять правил, которые объясняют почти всё остальное:

1. Модель никогда не выбирает профессии из всего каталога. Она видит только 20 кандидатов, которых нашёл поиск.
2. Любой ответ модели проверяется схемой. Идентификатор профессии должен быть из каталога, ссылка на ответ — из этой анкеты.
3. Если модель недоступна, ответ всё равно строится — по порядку поиска.
4. Постобработка одна для обоих путей, поэтому правила сортировки и лимиты одинаковые.
5. Для 1–4 классов направления выбирает таблица, а не модель.

## 1. Вход и досье

`lib/sofi-adapter.ts` переводит анкету во внутренний формат: ответы получают ссылки `A1`, `A2`, …, определяется тир по классу (`tierForGrade`), запоминается город.

`lib/ai/dossier.ts` собирает досье:

```ts
{
  answers: [{ ref: "A1", questionId, question, selected: ["Чинить механизмы"] }],
  student: { tier: "9-11", grade: 10, in_region: true },   // in_region = город Екатеринбург
  constraints: { format, free_only, time_limit, place },   // ограничения из анкеты
  emptyShare: 0.15,                                        // доля пустых ответов
  warnings: [...]
}
```

`emptyShare` — доля вопросов, где ребёнок выбрал «не знаю» или пропустил. Она потом влияет на уверенность: чем больше пустых ответов, тем ниже уровень.

Если ответов меньше двух (`min_signal_answers` в `config/age_policy.json`), дальше ничего не считается: клиент получает `low_signal` и просьбу продолжить анкету. Модель в этом случае не вызывается.

## 2. Каталог

`lib/runtime-catalog.ts` загружает каталог и приводит его к одной схеме `hybrid_v2`. Источник — либо Data Freeze 1 (`data/export/navigator.json`, 152 профессии), либо прежний каталог из базы. Пайплайн падает с ошибкой, если схема другая: молча работать на несовместимом каталоге он не будет.

## 3. Поиск

### 3.1 Группы запросов

`buildQueries` в `lib/ai/retrieval.ts` раскладывает ответы по четырём группам:

| Группа | Что попадает | Зачем |
| --- | --- | --- |
| `subjects` | предметы, профиль класса | что ребёнок изучает |
| `situations` | ситуативные выборы, «что нравится делать» | что ему нравится на практике |
| `direction` | выбранное направление | куда он сам хочет |
| `general` | все ответы вместе | общий профиль |

Два правила, которые появились после аудита:

```ts
// Вопросы про мероприятия, решение и готовность описывают процесс,
// а не интерес. Их варианты («профпробы в колледже», «кружки») тянули
// профессии образования в каждую анкету.
if (PROCESS_QUESTION.test(questionId + " " + question)) continue;

// В запрос уходят только выбранные варианты. Формулировка вопроса
// одинакова у всех и добавляет школьную лексику.
const selectedText = ans.selected.join(", ");
```

Каждый ответ внутри группы сравнивается с карточкой отдельно. Профессия берёт своё лучшее совпадение, а не среднее по группе.

### 3.2 Режим: semantic или lexical

```ts
semanticAvailable = false;
if (индекс совпадает с каталогом && векторы проверены) {
  try {
    queryVectors = await getEmbeddings(все ответы);  // один вызов на все ответы
    semanticAvailable = true;
  } catch { warnings.add("embedding_unavailable_lexical_fallback"); }
}
```

Семантика включается, только если индекс собран из текущего каталога, модель эмбеддингов та же, что при сборке, и шлюз ответил в срок (`embedding_timeout_ms` = 12 с). Любое нарушение — переход на текстовый поиск плюс предупреждение. Пользователь получает ответ в обоих случаях, меняется только качество.

### 3.3 Сходство и пороги

| Режим | Как считается | Порог |
| --- | --- | --- |
| `semantic` | косинус между вектором ответа и вектором карточки | 0.2 |
| `lexical` | доля общих слов с учётом основ слов и стоп-слов | 0.05 |

Пороги лежат в `config/rag.config.json`. Профессии ниже порога в кандидаты не попадают, поэтому у анкеты с одним ответом список короткий — это нормально.

### 3.4 Слияние RRF

Каждая группа даёт свой рейтинг top-20. Дальше рейтинги складываются по формуле:

```
балл(профессия) = Σ по группам  1 / (60 + место в группе)
```

Первое место в группе — 1/61 ≈ 0.0164, пятое — 1/65 ≈ 0.0154. Профессия, подтверждённая всеми четырьмя группами, получает около 0.065.

Смысл RRF: складывать сами числа сходства нельзя, у текстового счёта и у косинуса разные шкалы. Складываются только места.

Диапазон баллов узкий (0.016–0.066), поэтому рядом с баллом хранится сырое сходство — оно решает ничьи. Об этом ниже, в разделе про сортировку.

### 3.5 Отрасли, ссылки на ответы, покрытие

Кроме профессий поиск возвращает:

- `industryIds` — отрасли в порядке сходства;
- `evidence` — для каждой профессии ссылки на ответы, которые её вытянули (по ним строится объяснение);
- `coverageGap` — признак, что часть ответов не покрыта лексикой каталога. Считается по совпадению значимых слов ответа с текстами карточек.

## 4. Генерация моделью

Работает для 5–8 и 9–11 классов.

### 4.1 Промпт

`lib/ai/prompts.ts` собирает системный промпт из двух файлов: общий `prompts/common/1.0.2.md` и тировый, например `prompts/professions_9-11/1.3.0.md`. Хэш пары сверяется с `prompts/manifest.json` после нормализации переводов строк к LF, чтобы проверка совпадала на Windows и Linux; если файл правили без обновления манифеста, будет ошибка, а не тихая подмена текста.

В промпт подставляются переменные из `age_policy.json`: `max_items`, `min_items`, `max_sentence_words`, `min_signal_answers`, диапазон классов, версия схемы.

### 4.2 Что уходит в модель

Вторым сообщением — JSON:

```ts
{
  student: { tier, grade, estimated_age, in_region },
  answers: [{ ref: "A1", question, selected }],        // без служебных полей
  constraints,
  industries: [{ industry_id, name, hit_strength }],   // top-5 отраслей от поиска
  candidates: [{ profession_id, industry_id, name,
                 description, key_skills, trials, programs }],  // top-20 профессий
  activity_types: [{ activity_id, title, description, format, cost }],
  activity_link_contract: "..."
}
```

Модель видит только этих кандидатов. Придумать профессию вне списка она может, но проверка такой ответ отклонит.

### 4.3 Проверка ответа

`lib/ai/validate.ts` проверяет три вещи:

| Проверка | Что ловит |
| --- | --- |
| схема тира | лишние поля, неверные типы, слишком длинные тексты |
| идентификаторы | профессия не из каталога, отрасль не та, проба не из карточки |
| ссылки на ответы | `evidence_refs` указывает на несуществующий или чужой ответ |

Дополнительно: цифры в тексте разрешены только из карточки (`digitWhitelist`), чтобы модель не придумала зарплату или срок обучения.

### 4.4 Повтор и таймауты

```ts
for (let attempt = 1; attempt <= 2; attempt++) {
  // первая попытка с temperature 0.48
  // вторая — с temperature 0 и списком ошибок валидации,
  // плюс перечень разрешённых id и ссылок
}
```

| Параметр | Значение | Где |
| --- | --- | --- |
| попыток | 2 | `lib/ai/generate.ts` |
| таймаут попытки | 30 с | `config/llm.config.json` |
| общий дедлайн | 45 с | там же |
| предохранитель | 2 ошибки подряд → пауза 60 с | `lib/ai/llm/circuitBreaker.ts` |

Если ответ содержит цифры, которых нет в карточке, есть мягкая чистка (`softSanitizeResponse`): она убирает числа и проверяет снова. Если и это не помогло — вторая попытка, потом резервный путь.

### 4.5 Особый случай 1–4

Для младших классов модель вызывается, но список профессий ей не передаётся (`candidates: []`). Направления и пробы выбирает таблица `lib/ai/elementary.ts`: вариант ответа → направление → отрасль → до трёх проб с фильтрами по классу, формату, цене, времени и городу. Направление попадает в ответ, только если его подтверждают минимум два ответа.

Из ответа модели берутся только `summary` и `next_step`. Поля `interest_tags` и `activity_ids` перезаписываются таблицей, включая текст «почему» — он заменяется одной общей фразой.

## 5. Резервный путь

`lib/ai/fallback.ts` включается, когда модель недоступна, ответила не по схеме дважды или истёк дедлайн. Логика простая: берутся первые пять профессий из результатов поиска, у которых есть хотя бы одна ссылка на реальный ответ.

Что при этом теряется: текст модели. Что сохраняется: состав и порядок профессий, объяснения из ответов, уверенность, предупреждения.

## 6. Постобработка

`lib/ai/postprocess.ts` — общий финальный шаг.

### 6.1 Фильтры

Профессия остаётся в списке, если она есть в каталоге, у неё есть хотя бы одна ссылка на ответ анкеты, а предложенные пробы и программы принадлежат её карточке. Всё остальное отбрасывается молча, счётчик отброшенных попадает в предупреждение `no_valid_hypotheses`.

### 6.2 Порядок

```ts
sort((a, b) => {
  сила совпадения            // strong > moderate > weak
  балл RRF, допуск 5 %       // 5 % от лучшего балла: меньше — считаем равными
  сырое сходство             // косинус или текстовый счёт, без RRF
  уверенность                // high > medium > low
  profession_id              // последний рубеж, чтобы ответ был воспроизводим
});
```

Допуск нужен из-за узкой полосы RRF: без него любые две профессии выглядели равными, и порядок задавал идентификатор. Именно так «Инженер-механик» с `prof_001` оказывался первым в 9 анкетах из 13 в текстовом режиме и в 7 из 13 в семантическом.

### 6.3 Ограничения и обрезка

- не больше двух профессий из одной отрасли;
- не больше `max_items` гипотез: 5–8 классы — 4, 9–11 — 5;
- номера `rank` проставляются после обрезки.

Если из-за лимита по отрасли список короче максимума, он остаётся коротким. Это осознанный выбор: лучше две точные профессии, чем пять с тремя случайными.

### 6.4 Уверенность

`lib/ai/confidence.ts` считает уровень по правилам из `config/confidence_rules.json`. Учитывается:

- сила совпадения от модели;
- подтверждение поиском: нашлась ли профессия и её отрасль;
- сколько независимых ответов её подтверждают;
- доля пустых ответов;
- есть ли пробел покрытия.

Для 1–4 уверенность не показывается, для 5–8 выводится словами, для 9–11 — уровнем.

### 6.5 Объяснение

`evidenceReason` собирает текст из ответов, которые вытянули профессию: «В твоих ответах: «Чинить механизмы», «Собирать конструктор». Это одна из причин рассмотреть профессию…». Тот же текст используется и в резервном пути, поэтому объяснение не зависит от того, ответила модель или нет.

## 7. Кэш

`lib/ai/cache.ts`, в памяти процесса, живёт один час. Ключ — хэш от досье, результатов поиска, версии промпта, версии каталога и версии конфигов.

Кэшируются только полноценные ответы: модель ответила и поиск был семантическим. Деградировавшие ответы не кэшируются, иначе разовый сбой шлюза закреплялся бы на час.

## 8. Что получает клиент

| Поле | Смысл |
| --- | --- |
| `status` | `ok`, `fallback`, `low_signal`, `no_match` |
| `summary` | вступление от модели или шаблон |
| `industries` | отрасли с пояснением (5–8, 9–11) |
| `interest_tags` | направления (1–4) |
| `activity_ids` | пробы (1–4) |
| `hypotheses` | до 5 гипотез: профессия, отрасль, `why`, `evidence_refs`, сила, пробы, программы, уверенность |
| `next_step` | что сделать дальше |
| `warnings` | технические пометки, перечислены ниже |
| `generation` | режим поиска, режим генерации, тир, версии промпта и каталога, число попыток |
| `disclaimer` | «предварительная подсказка, а не диагностика» |

## 9. Деградации

| Что случилось | Что получит пользователь | Пометка |
| --- | --- | --- |
| нет ключа шлюза или таймаут эмбеддингов | тот же ответ на текстовом поиске | `embedding_unavailable_lexical_fallback` |
| индекс собран из другого каталога | текстовый поиск | `catalog_index_stale_lexical_fallback` |
| индекс собран другой моделью | текстовый поиск | `catalog_index_model_conflict_lexical_fallback` |
| модель не ответила или ответила не по схеме | гипотезы по порядку поиска | `llm_fallback_used` |
| часть ответов не покрыта каталогом | список короче | `coverage_gap` |
| все профессии отброшены фильтрами | пустой список, `no_match` | `no_valid_hypotheses` |
| пробы только очные, а ребёнок не в Екатеринбурге | тот же список | `trials_only_offline_out_of_region` |

## 10. Где что настраивается

| Файл | Что задаёт |
| --- | --- |
| `config/age_policy.json` | тиры, лимиты гипотез, что показывать, минимум ответов |
| `config/rag.config.json` | пороги, top-k, `rrf_k`, допуск сортировки, MMR |
| `config/llm.config.json` | модель, температура, лимиты токенов, таймауты, предохранитель |
| `config/confidence_rules.json` | правила уровней уверенности |
| `prompts/manifest.json` | какие промпты и схемы привязаны к тиру |

## 11. Чего AI-часть не делает

- Не считает RIASEC ученика. Профиль RIASEC есть у профессий, но с ответами не сравнивается; типы показываются в карточке как описание профессии.
- Не учитывает региональную востребованность и число вакансий. Эти поля есть в каталоге, но в поиске и сортировке не участвуют.
- Не проверяет факты о зарплате и программах обучения: они берутся из карточки как есть.
- Не гарантирует разнообразие отраслей: лимит «два из отрасли» ограничивает повторы, но не разбавляет список намеренно.
- Не является диагностикой. Это подсказка, что посмотреть и попробовать.
