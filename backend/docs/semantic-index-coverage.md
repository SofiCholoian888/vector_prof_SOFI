## Поля поиска и навыки

Для профессии индексируются название, отрасль, практическая деятельность школьника, описания для 1–4, 5–8 и 9–11 классов, названия разрешённых навыков и условия их применимости. Для отрасли индексируется название. ID профессии, отрасли, программ и проб хранятся в метаданных для привязки результатов к каталогу.

Из 677 связей «профессия — навык» в текст вошли все 588 со статусом `yes_provisional`. Фильтр исключил 80 связей `conditional_scope` и 9 связей `no_pending_review`. Навыки идут по убыванию `importance`. Числовые веса не перемножаются при формировании текста. Правило отбора задано в [методологии экспорта](../../docs/ai_integration.md).

## Проверка в пайплайне

Локальный запуск штатной функции `runSofiPipeline` с живым шлюзом и ответом «Чтение технических чертежей и схем» сформировал два поисковых запроса. После объединения результатов поиск вернул 25 профессий и `generation.retrievalMode=semantic`. Один ответ анкеты проверяет стадию поиска, генерация текста в этом сценарии работает в режиме `retrieval_only`.

При отключённой конфигурации шлюза тот же запрос дал `lexical` и 20 профессий. Интеграционный тест также возвращает HTTP 503 из тестового шлюза при валидном индексе и проверяет режим `lexical` и предупреждение `embedding_unavailable_lexical_fallback`.

## Воспроизведение

Запускать из `backend/` после `npm ci`. Для сборки и живой проверки задать в окружении `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_EMBEDDINGS_MODEL=EmbeddingsGigaR` и выключить `USE_MOCK_EMBEDDINGS`.

```sh
node --experimental-strip-types scripts/build-embedding-index.mjs --dry-run
node --experimental-strip-types scripts/build-embedding-index.mjs --apply
node --experimental-strip-types scripts/build-embedding-index.mjs --check
node --experimental-strip-types --import ./tests/register-app-alias.mjs scripts/check-semantic-pipeline.mjs
```

Если для HTTPS нужен прокси из окружения, в Node 24 можно добавить `--use-env-proxy` при запуске сборщика. Режим `--check` проверяет уже записанный файл без сети, выводит несовпадающие ID и завершается с ненулевым кодом при нарушении контракта. Для проверки без настроек шлюза запустить последнюю команду с `--expect-lexical`.
